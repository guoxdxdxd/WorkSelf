# WorkSelf 工作助手

> 项目总览、安装与仓库结构见仓库根 [README](../README.md)。

不是把桌面任务管理器搬进 DSH，而是给 AI 一个**可用的工作环境**：它能读懂你的项目、事项之间的依赖、每个人怎么打交道，在你遇到问题时给出贴合的建议，并把结论沉淀回去，越用越准。

## 设计取向

- **不是桌面项目管理器的复刻**：去掉了日历、统计、工作池、等待等界面，只保留与「让 AI 理解并推进工作」直接相关的四面：工作台、项目、联系人、设置。
- **一切为了上下文**：事项、日志、人都能一键进对话；AI 用 `workos_context` 展开项目、依赖、人员经验，而不是凭消息里的摘要回答。
- **一切为了沉淀**：方案、日志、打交道经验写回 Markdown；下一次提问，环境更完整。
- **Agent 设定分三层**：工作区 `AGENTS.md`（三条铁律：认路 / 有据 / 留痕）是常驻宪法，`workos-persona` / `workos-maintain` 是回答与写回的随取手册，工具描述只讲契约、不重复规则。姿态借鉴 superagent 的注意力原则：少打扰、一次一问、按影响停止、诚实。

## 三个动作

1. **建模**：项目和事项有目标、负责人、涉及人员、依赖、到期和日志；联系人带「打交道经验」。
2. **提问**：在项目、事项、日志或联系人上点「加入对话」，输入框会出现一条【工作上下文】引用；你接着问问题，AI 会先展开上下文再回答。
3. **自动沉淀**：每轮对话后，AI 先判断内容属于哪个项目/事项（没有就补建），再把事实、决定、日志、负责人/涉及人员变化、打交道经验写回 Markdown；遇到档案里没有的人，先问清资料再补进联系人；日志写清前因后果与关联，不写流水账。下次提问它就知道更多。

## 日报 / 周报

汇报分两种口径，写在两个地方：

- **个人汇报**：工作台顶部「汇报」按钮。汇总**全部项目**的日志与进展，写回 `data/日报/YYYY-MM-DD.md`、`data/周报/起始_结束.md`；列表在工作台的「个人汇报」卡片里。
- **项目汇报**：项目详情里的「项目汇报」卡片。只汇总**当前项目**，写回该项目文件夹的 `汇报/日报/`、`汇报/周报/`，与 `事项/` 平级。

生成方式两种都支持：

- **手动生成**：选一天或一个时间段 → 确认后自动新建对话，把提示词发给助手；助手用 `workos_report_data`（项目汇报带 `uid`）读取该口径的日志、项目进展和在办事项，写成含生成时间、汇报时段、简介、详细内容的汇报，再用 `workos_report_save` 写回对应目录。
- **自动生成**：同一个弹窗的「自动生成」页签选频率（每天 / 每周五 / 每周一）、时间、内容（当天日报 / 本周周报 / 上周周报），确认后向 DSH 添加自动化任务；到点自动在专用对话里生成并写回，任务可在 DSH 的自动化任务面板暂停或删除。
- **查看与编辑**：两张汇报卡片都按生成时间倒序列出汇报，展示汇报时段与简介；点开弹窗看详细内容，并可手动修改简介/详细内容后保存。
- 生成过程在新建的对话里可见；驾驶舱会在生成开始后自动轮询刷新，也可以点卡片右上角「刷新」。

## 入口

会话**右侧边栏** → 开始页工具卡片「工作驾驶舱」。首次打开会在当前工作区创建 `workos/`（已有文件不覆盖），同时：

- 联系人里加入默认的「我」（可编辑），新事项负责人默认「我」；
- 在工作区根目录写入 `AGENTS.md` 的助手设定段（已有内容保留；助手段会随插件升级原地刷新），DSH 会自动把它作为本工作区的 agent 指令加载。

四个页签：**工作台 / 项目 / 联系人 / 设置**。

- 工作台：在办、逾期、阻塞、最近日志；每条都能加入对话。另有「日常工作」卡片，列出不属于任何项目的临时事项。
- 项目：目标与背景、事项列表；项目列表每行可直接「加入对话」，不用先进详情；支持「全部 / 未完成」快筛（默认未完成），事项详情改为**弹窗**（字段、依赖、相关人经验、日志、记日志、编辑/删除）；所有卡片可折叠。项目详情里的负责人、涉及人员可直接点击进入联系人编辑，依赖事项点击后在弹窗里查看它自己的详情（可返回）。
- 联系人：资料 + 打交道经验；可加入对话、编辑、删除（删除前确认，并列出仍引用这个名字的项目/事项）。
- 设置：目录、索引、迁移旧档案（单文件 → 文件夹）。

## 工作区 Agent

初始化会生成 `<工作区>/AGENTS.md`，内容是一份可直接编辑的助手设定，正文维护在仓库 `assets/workos-agent.md`。它按三条铁律组织：

- **认路**：完整工作舱地图（`data/` 人与经验、`work/{部门}/{年}/项目/{项目名}/README.md` + `事项/` 独立文件 + `汇报/`、`日常工作/`）与查找顺序 `workos_overview → workos_context → workos_query → workos_search → workos_read`；README 只是索引，不猜文件名。
- **有据**：看到【工作上下文】先 `workos_context`，再查依赖、相关人的打交道经验与同项目其他事项；只依据档案回答，外部信息标来源，不编造。
- **留痕**：每轮对话先判归属（日常工作还是项目事项）再回答，答完五步写回（判归属 → 定位 → 挂靠 → 补建 → 说落点）；日志一条对应一次变更：前因 → 事件 → 结果与下一步 → 关联；同一件事合并、补充改原条目；新联系人先查名单、问清资料再 `contact.add`；删除前确认。

回答结构：判断 → 动作（谁 / 何时 / 怎么说）→ 风险 → 检查点。档案结构约束：一个项目一个文件夹（README + 事项/ 每事项一个文件），写入走 `workos_update`（项目 / 事项 / 日志 / 联系人 / 经验）与 `workos_report_save`（汇报），不手工建文件。

DSH 的 `dsh-agent-instructions` 会在该工作区的每个会话里自动加载这份文件，不需要手动选 agent。文件里原有的其他内容不会被覆盖；助手段用 `<!-- workos-agent:start -->` 标记，插件升级后下次打开驾驶舱会把它原地刷新成最新规则。

## 项目模型

项目新建时记录名称、类型、负责人、涉及人员、目标、关键节点和背景；这些都能在项目详情的「编辑项目」里再次查看和修改（另外可改状态、优先级、开始日期）。改项目名会同步重命名项目文件夹，并更新年度概述里的链接。

## 事项模型

每个事项一个独立的 Markdown 文件（`事项/w{编号} {事项名}.md`）：

- 名称、详情、状态、到期
- 负责人（从联系人单选）、涉及人员（从联系人多选）；点人员名字进入联系人编辑
- 依赖（同项目的其他事项，多选；前置未完成时显示被卡住）；详情里点依赖直接打开该事项的详情弹窗
- 日志：时间 / 事件 / 解决方案；日志写在同一个事项文件的 `## 日志` 表格里，每条日志可加入对话

事项标题变了，它的文件名会跟着重命名；事项 id（`w` + 数字）在项目内唯一。

状态默认「进行中」：AI 从对话里补建的事项不会自己写「已完成」，只有你明确说这件事做完了、或自己在界面上把状态点成「已完成」，它才会改。界面手动新增事项仍可选「未开始」。

删除事项时，被其他事项依赖会拒绝并说明是谁依赖。

## 日常工作（不属于任何项目的事项）

临时性的工作不硬塞进项目：顶部「汇报 / 添加事项 / 刷新」中间的「添加事项」打开事项弹窗，比项目里的新增多一个「所属项目」下拉框——选项目就是普通项目事项，留空就落到日常工作。

- 目录：`workos/work/{部门}/{年}/日常工作/`，每个事项一个 md 文件，文件名前缀是添加时的日期时分秒（`YYYY-MM-DD HH-MM-SS 事项名.md`）。
- 文件内部与项目事项一致：frontmatter 字段 + `## 详情` + `## 日志`；`uid: 0`、`scope: daily`，事项 id 为 `d1`、`d2`…，没有依赖和项目 README。
- 工作台「日常工作」卡片列出这些事项，可加入对话、看详情、改状态、记日志、编辑、删除。
- 个人日报/周报会把日常工作一起汇总（`uid: 0 / 日常工作` 桶）；项目汇报只含该项目，不含日常工作。
- AI 自动归档时先判断归属：一次性的、没有独立项目目标 / 节点 / 交付物的临时工作 → 日常工作；有独立目标、交付物、节点、预算 / 客户或需持续跟进 → 先 `workos_search` 找项目，找不到再问或建项目。不要为临时工作造项目，也不要把临时工作硬塞进无关项目。
- 给 AI 的上下文标记用 `uid=0 item=d1`，`workos_context` 会展开日常工作事项与负责人经验；归档时 `item.add` 不传 uid（或 `uid: 0`）即可新建日常工作事项。

## 上下文怎么进到聊天

点「加入对话」后，输入框插入一条引用，发送时以 Markdown 引用块进入消息。引用里带 uid / item / log，以及该内容所在文件的**路径**（工作区内用相对路径，只列一次，不再另列项目文件）：

```
【工作上下文】uid=1001 item=w3 log=2 path="workos/work/我的工作/2026/项目/示例展会/事项/w3 展台设计.md"
项目：示例展会（进行中，目标：12 月 20 日顺利开展）
事项：展台设计 · 初稿（w3，进行中，到期 2026-11-28）
负责人：张三；涉及人员：李四、王五
依赖：w1 确认展位信息（已完成）
日志：2026-11-19 16:20 · 张三报价比上季度高 30%
```

技能 `workos-persona` 规定：看到标记先调 `workos_context`，拿到项目、事项、依赖状态、人员资料与**打交道经验**，再给判断。所以消息里是摘要，回答用的是最新档案；文件路径让模型能直接定位文件，而不是猜。

## 数据

**Markdown 是唯一真相**：`<当前工作区>/workos/`

```
workos/
├── data/workos/contacts.md    联系人（含打交道经验）
├── data/workos/meta.yaml      项目 uid 与类型
├── data/日报/YYYY-MM-DD.md     个人汇报（汇总全部项目）
├── data/周报/起始_结束.md       个人周报
├── data/经验.md
└── work/{部门}/{年}/
    ├── 项目/{项目名}/
    │   ├── README.md              项目主档：目标与背景、事项索引、项目进展、复盘
    │   ├── 事项/w{编号} {事项名}.md  一个事项一个文件：字段、详情与日志
    │   └── 汇报/日报|周报/         项目汇报（只汇总该项目）
    └── 日常工作/
        └── YYYY-MM-DD HH-MM-SS {名称}.md  不属于任何项目的临时事项，一个事项一个文件
```

一个项目一个文件夹，项目再大也只在文件夹里生长；事项各自成文件，日志写在所属事项文件里，不单独建文件。不属于项目的事项放 `日常工作/`，不硬塞进项目也不为它造项目。SQLite（`data/workos/.index/`）只做检索，可删可重建。旧版「一个项目一个 md」的档案仍可读取，第一次写入或点「迁移旧档案」时自动拆成文件夹结构。

## 工具与技能

| 工具 | 用途 |
|---|---|
| `workos_context` | 展开【工作上下文】：项目、事项、依赖、人员经验、日志（`uid=0` 为日常工作） |
| `workos_overview` | 全局：在办、逾期、阻塞、最近日志、日常工作 |
| `workos_query` | 结构查询 projects / items / logs / contacts |
| `workos_search` | 全档案全文检索（中文两字词可用） |
| `workos_read` | 读任意 Markdown 原文（日常工作可给 `itemId: d1`） |
| `workos_update` | 建项目、加/改/删事项、记日志、补经验、写回（不传 `uid` = 日常工作） |
| `workos_report_data` | 读取某时段日志/项目进展/在办事项，专供生成日报周报（传 `uid` 只取一个项目；个人汇报含日常工作） |
| `workos_report_save` | 写回汇报：不传 `uid` 写 `data/日报`、`data/周报`（个人），传 `uid` 写项目文件夹的 `汇报/日报`、`汇报/周报` |

技能：`workos-persona`（带环境回答）、`workos-maintain`（归档与信息维护）。工作区 agent 设定正文在 `assets/workos-agent.md`，初始化时写入 `AGENTS.md`，插件升级后原地刷新。
