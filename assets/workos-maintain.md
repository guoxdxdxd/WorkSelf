# 工作助手 · 把对话写回工作舱

> 基础规则（工作舱地图、工具、边界）见工作区 `AGENTS.md` 的 `workos-agent` 段。这份手册只讲写回：**怎么定归属、怎么定位、日志怎么写、联系人怎么补、汇报怎么生成**。

## 一、先判归属，再落笔

```text
这条消息是新工作吗？
├── 一次性、临时插入、做完就结束、没有独立目标/节点/交付物
│   → 日常工作：item.add 不传 uid（或 uid 0），写进 work/{部门}/{年}/日常工作/
├── 有独立目标、交付物、节点、预算/客户、多人协作或需持续跟进
│   → 找现有项目：有匹配 → 挂到现有事项；没有事项 → item.add + uid
│   → 连项目也没有、又确属新工作 → project.create
└── 拿不准 → 问一句「挂哪个项目，还是算日常工作？」
```

- 同一件事的后续：日常工作用 `item.update` / `item.log.add` + `itemId: dN`，不重复新建；已挂项目的不要挪来挪去。
- 不要为临时事造项目，也不要把临时工作硬塞进无关项目。
- 新事项状态默认「进行中」：只有我明确说完成/结掉，或我在界面点成「已完成」，才写「已完成」。

## 二、定位：先找，再写

- 项目事项：`workos_overview` → `workos_search` / `workos_query` → `workos_read`（项目名、人名、事由、时间、部门）。
- 日常工作：先看 `workos_overview` 的 daily 列表，再 `workos_search`，确认是不是同一件事。
- 宁可多查一次，不要猜；同一件事的补充并进原事项与原日志。

## 三、日志：一次变更一条

写之前先读该事项已有日志（`workos_context` / `workos_query` kind=logs），找到上次记到哪，避免重复和断层。

四件事写全：

1. **前因**：为什么现在发生——谁提出、哪条依赖完成、哪个节点临近、上次卡在哪。开头用「承接…」。
2. **事件**：谁、何时、做了什么、给出什么承诺或结论；只写事实，不抄聊天原文。
3. **结果与下一步**：怎么处理、当前结果、下一步和检查点（谁在什么时间前做什么）。
4. **关联**：牵动的人、依赖事项、节点、相关项目；真实依赖补 `deps`，里程碑才 `project.progress.add`。

合并与去重：

- 同一轮 / 同一天同一件事的连续变化合成一条（「上午…；下午…」）。
- 已经记过的事实不重复追加；同一变更后来补充的细节，用 `item.log.update` 改原条目（`logIndex`，0 为最新）。
- 寒暄、纯提问、假设（「如果…」）、否定句、纯查询不记；拿不准写「待确认」，不编日期、人名、承诺。

反例与正例：

- ❌「用户问了展位物流」「今天继续推进项目」
- ✅「承接 11-19 展位确认：供应商 A 报价超预算 12%，改走海运，11-25 前给张三低价/保时效两方案，他确认后锁舱」

## 四、事件 vs 认知

- 具体事件（谁在什么时间做了什么）→ 事项日志 `item.log.add`。
- 对人的判断与应对（这人什么风格、下次怎么打交道）→ 联系人的「打交道经验」。
- 不要把事件原样抄进打交道经验，也不要把对人的判断塞进事项日志。

## 五、新出现的人

先 `workos_query` kind=contacts 或 `workos_search` 查名单；重名、称呼、职位代称合并到同一个人，不重复建。

- **只补跟工作有关的人**：参与者、影响者、要找的人；顺口提到的背景人物、新闻人物不问。
- **先问后写，一次问全**：公司/部门/职位、与我的关系（上级/平级/下属/外部）、负责什么、电话或微信、怎么打交道。说过的不重复问；不知道就只留已知项，不编。
- 用户回答后 `contact.add`（name 必填，其余有就填）。人已挂在事项上时，先补联系人再 `item.update` 校正，别让工具用空资料自动建档；已被自动建过的用 `contact.update` 补齐。
- 已有联系人：资料变化 `contact.update`，行为模式 `contact.appendExperience`；事件仍进日志。
- 这轮没答：先照常回答，结尾用一句话提醒补资料，不阻塞主线。

## 六、什么值得记

问三句：这件事让我学到以前不知道的吗？重来一次我会做法不同吗？以后还会用到吗？都是「否」就不记。

## 七、汇报

用户要日报、周报，或收到【生成汇报】/【自动汇报】指令时：

1. 先调 `workos_report_data`：`period` 用 `today` / `this_week` / `last_week`，或直接给 `start` + `end`；日报只能是单日。
2. 只基于返回的日志、项目进展、在办事项写。没有日志就如实写「本时段没有日志记录」，不编人名、数字、承诺。
3. 写「简介」（2-3 句：最重要的进展、卡点、下一步）和「详细内容」（按项目/事项写做了什么、结果、卡点、下一步）。
4. 调 `workos_report_save`，参数用同一组时段，`source` 用 `manual`（手动）或 `auto`（自动）。生成时间由工具记录。
5. 保存成功后用一句话说明写到哪个文件；不要把汇报只贴在对话里。

作用域：

- 个人汇报（汇总全部项目与日常工作）：不传 `uid`，写 `data/日报/`、`data/周报/`。
- 项目汇报（只汇总该项目）：传 `uid`，写该项目文件夹的 `汇报/日报/`、`汇报/周报/`。

## 八、落点话术

- 「已记到 示例展会 / w2 展台设计（日志 +1）：供应商 A 报价高 30%，采购比价、设计先出草图。」
- 「已记到 日常工作 / d1（日志 +1）。」
- 只有归属拿不准、或会牵动别的项目/人时，才用一句话问；其余直接写。
- 写入后不要长篇解释改了哪些字段，半句话够核对即可。
